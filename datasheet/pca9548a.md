# PCA9548A Firmware Implementation Specification

## 2026-09-26 Driver Audit (1.0.0)

Rechecked the PDF control register, STOP activation, address table, reset and
I2C timing. The PDF remains authoritative; this is an engineering reference,
not a replacement for package drawings, electrical qualification or errata.

`unit_pahub_mask_set()` accepts `0x00..0x3F`; zero disables every board port.
`unit_pahub_mask_get()` returns the entire hardware byte for diagnostics.
`channel_get()` returns `0xFF` for zero, multi-channel or non-board masks.
Automatic downstream reads/writes select exactly one port under the BSP's
recursive Port A bus lock, so selection plus transfer is atomic against every
Port A user. Readback updates cached routing. If a transfer on a cached
route is NACKed, the driver reads the register back: if the port is no
longer routed (hub power-on reset, § 3.6) it reselects and retries once;
otherwise the cache stays valid and the error is returned. Control writes
are retried only after a NACK. With `CONFIG_PAHUB_AUTO_RECOVER`, a timeout
triggers the bus-clear sequence; control writes are then retried once.

Init writes `0x00` and verifies it by readback, so a missing hub or a foreign
device at the address fails init. Init/deinit are reference counted per user.
`unit_pahub_recover()` issues the ESP-IDF bus-clear sequence (nine SCL pulses)
and then resynchronises the register; retries alone cannot release a bus held
low. The final deinit disables ports best effort and retains ownership only if
the device release fails. Hardware qualification remains necessary.

# 2. Device Overview

## 2.1 Device Function

The **PCA9548A** is an **8-channel bidirectional I²C switch** that allows a single I²C master to communicate with multiple downstream I²C buses.

The device routes the upstream I²C bus (SDA/SCL) to one or more of eight downstream channels:

```
SC0/SD0
SC1/SD1
SC2/SD2
SC3/SD3
SC4/SD4
SC5/SD5
SC6/SD6
SC7/SD7
```

Each channel can be individually enabled or multiple channels may be enabled simultaneously.

---

## 2.2 Intended Use

Typical applications:

* Resolving I²C slave address conflicts
* Multiplexing multiple identical sensors
* Distributing I²C bus capacitance
* Voltage translation between I²C buses
* System management bus (SMBus) switching

---

## 2.3 Key Capabilities

* 8-channel bidirectional I²C switch
* I²C Standard Mode (100 kHz)
* I²C Fast Mode (400 kHz)
* Voltage translation between 1.8 V, 2.5 V, 3.3 V, and 5 V buses (via the pass-gate and external pull-ups)
* 5 V-tolerant inputs
* Active-low RESET input (recovers a stuck downstream bus without removing power)
* Three hardware address pins (A0, A1, A2) → up to 8 devices on one bus
* Channel selection through the I²C bus (single 8-bit control register)
* All channels deselected on power-up (glitch-free power-up)
* Supports hot insertion
* Low ON resistance pass-gate switching
* Latch-up > 100 mA per JESD 78 Class II
* ESD: ±2000 V HBM (JS-001), ±1000 V CDM (JESD22-C101); feature list also cites 200 V machine model (A115-A)
* Operating temperature −40 °C to 85 °C

## 3.8 Pass-Gate / Voltage Translation

The pass-gate transistors let VCC clamp the maximum voltage passed between buses, enabling level translation. For the device to act as a translator, the pass voltage (V_pass) must be **≤ the lowest bus voltage**.

### Switch Output Voltage Vo(sw) (Vi(sw) = VCC, ISWout = −100 µA)

| VCC           | Min    | Typ   | Max   |
| ------------- | ------ | ----- | ----- |
| 5 V           |        | 3.6 V |       |
| 4.5 V – 5.5 V | 2.6 V  |       | 4.5 V |
| 3.3 V         |        | 1.9 V |       |
| 3.0 V – 3.6 V | 1.6 V  |       | 2.8 V |
| 2.5 V         |        | 1.5 V |       |
| 2.3 V – 2.7 V | 1.1 V  |       | 2.0 V |

* Example (§9.2.1): main bus 5 V, downstream buses 3.3 V and 2.7 V → V_pass must be ≤ 2.7 V. V_pass(max) is 2.7 V when VCC ≤ 4 V (Figure 9-2), so VCC could be 3.3 V. External pull-ups then bring each bus to its target level.
* When voltage translation is **not** needed, tie VCC and all pull-up reference voltages to the same supply.

# 6. Hardware Integration Constraints

## Pull-Up Resistors

Required on:

* SDA
* SCL
* SD0–SD7
* SC0–SC7

---

## Pull-Up Resistance Equations

### Minimum Pull-Up

```
Rp(min) = (VDPUX − VOL(max)) / IOL
```

---

### Maximum Pull-Up

```
Rp(max) = tr / (0.8473 × Cb)
```

Where:

| Parameter | Meaning         |
| --------- | --------------- |
| VDPUX     | pull-up reference voltage of that channel |
| VOL(max), IOL | 0.4 V at 3 mA when VDPUX > 2 V; 0.2 × VDPUX at 2 mA when VDPUX ≤ 2 V (Figure 6-2) |
| tr        | maximum rise time: 1 µs standard mode, 300 ns fast mode |
| Cb        | bus capacitance |

If multiple channels are enabled at once, the master-side IOL is the sum of the currents through every active pull-up.

---

## Maximum Bus Capacitance

```
Cb ≤ 400 pF
```

Estimate Cb as the PCA9548A Cio(off) plus wiring, connectors, traces and every slave on the channel. With several channels enabled, slaves on all active channels add to Cb.

## Layout Guidance (§11)

* Give ground pins a low-impedance path (wide pours, multiple vias) to a ground plane.
* Decouple VCC with a larger bulk capacitor and a smaller high-frequency capacitor.
* Keep SCn/SDn traces short and narrow (about 5–10 mil) to limit parasitic capacitance.
* With voltage translation, split planes isolate the VDPUM and VDPU0–VDPU7 pull-up rails.

# 8. Addressing and Device Identification

## I²C Address Format

The 7-bit slave address has a fixed upper nibble `1110` and three hardware-selectable bits set by the A2/A1/A0 pins:

```
MSB                          LSB
 1   1   1   0   A2  A1  A0  | R/W
```

* R/W = 0 → write, R/W = 1 → read.
* A0–A2 must be tied directly to VCC or GND and must **not** change between START and STOP.
* Figure 8-4 and Table 8-1 agree on the `A2 A1 A0` bit order. (Plain-text PDF extraction scrambles the figure labels to `A1 A2 A0`; the rendered figure does not.)

# 9. Communication Protocol

The device exposes a **single 8-bit control register** with no sub-address/register pointer. A write sends the slave address then the control byte; a read returns the control byte directly.

## Write Transaction

```
START
DEVICE_ADDRESS + W
ACK
CONTROL_BYTE        (channel mask)
ACK
STOP
```

* The selected channel(s) become active **only after the STOP** condition, which guarantees every SCn/SDn line is high at connection.
* TI requires the STOP immediately after the acknowledge cycle.
* There is no limit on the number of bytes sent; if multiple bytes are written, the device **keeps the last byte received**.

## Read Transaction

```
START
DEVICE_ADDRESS + R
ACK
CONTROL_BYTE        (current channel mask, from device)
NACK (from master)
STOP
```

* A read returns the live value of the control register (the current channel mask). No command/pointer byte is required.
* The master signals end-of-data with a NACK on the final byte before STOP.
* The §8.6.3.2 prose mentions a command byte, a restart and "data from the SCn/SDn channel"; that text does not match this device. Figure 8-7 (single-byte read shown above) is authoritative.

# 15. Reset Behavior

## Hardware Reset (RESET pin)

Signal:

```
RESET (active low)
```

* Asserting RESET low for at least `t_W(L) = 6 ns` resets the registers and the I²C state machine and deselects all channels.
* RESET must be connected to VCC through a pull-up resistor when not actively driven.
* Primary use: recover when a downstream I²C bus is stuck low, without cycling power.

### RESET Errata (important)

If the RESET pin is driven **higher than VCC**, current flows from RESET into VCC and pulls VCC above its normal level. **Always design so RESET voltage ≤ VCC.**

## Power-On Reset (POR)

* On power-up, an internal POR holds the device in reset until VCC reaches VPORR (rising). Registers and the I²C state machine then initialize to defaults (all channels deselected).
* For a deliberate power-reset cycle, VCC must be lowered **below VPORF** and then ramped back up above VPORR. A glitch that stays above VPORF does not reset the part.
* See §3.6 for VPORR / VPORF values.

## Reset Effects

Both RESET and POR cause:

* I²C state machine reset
* Control register cleared to `0x00`
* All channels deselected

## Reset Propagation

```
RESET → SDA clear delay ≈ 500 ns (max)
```

| VCC range     | Min | Typ | Max | Unit |
| ------------- | --- | --- | --- | ---- |
| 4.5 V – 5.5 V | 4   | 10  | 20  | Ω    |
| 3.0 V – 3.6 V | 5   | 12  | 30  | Ω    |
| 2.3 V – 2.7 V | 7   | 15  | 45  | Ω    |

## Propagation Delay (t_pd)

The pass-gate propagation delay is the RC time constant of R_ON and the load capacitance:

| Condition              | Max  | Unit |
| ---------------------- | ---- | ---- |
| R_ON = 20 Ω, CL = 15 pF | 0.3  | ns   |
| R_ON = 20 Ω, CL = 50 pF | 1    | ns   |

# 21. Driver Initialization Sequence

```
1 Apply VCC (rise time 0.01–100 ms)
2 Wait for power-on reset completion
3 Confirm I²C communication
4 Write control register (0x00)
```

TI specifies no delay from POR release to the first I²C transaction, and t_REC(STA) = 0 ns after RESET. Any start-up delay is a system policy for supply settling.

# 22. Runtime Operation Sequences

## Enable Single Channel

```

```
channel 3 → 0x08
```

## Enable Multiple Channels

```
register = bitmask
```

Example:

```
channels 0,2,4 → 0b00010101

# 24. Required Safety and Correctness Rules for Code Generation

1. Always issue STOP after writing control register
2. Channel activation occurs only after STOP
3. Respect I²C timing constraints
4. Ensure SDA stable during SCL high
5. Do not change A0–A2 during transaction
6. Always provide pull-ups
7. Reset channel state after reset
8. Ensure RESET voltage ≤ VCC
9. Bus capacitance must not exceed 400 pF

---

Minimum driver must implement:

* channel enable/disable
* reset handling

# 29. Final Implementation Intent

A generated firmware driver should:

* Provide channel selection APIs
* Handle multiple channel enable masks
* Maintain correct I²C protocol timing
* Correctly reset device state
* Prevent invalid address changes during transactions

---

## Common Implementation Mistakes

1. Forgetting STOP after register write
2. Enabling channels before STOP
3. Exceeding I²C bus capacitance
4. Omitting pull-ups on downstream buses
5. Driving RESET above VCC
6. Not clearing channels after reset

# 30. Board Context: M5Stack Unit PaHub v2.0 (SKU U040-B)

This PCA9548A is the core IC of the **M5Stack Unit PaHub v2.0** used in this project. When writing a board-level driver, apply these board-specific constraints on top of the generic chip behavior above. (See `pahub.md` for the full board specification.)

## 30.1 Board Differences vs. Raw Chip

| Aspect            | Raw PCA9548A          | PaHub v2.0 board                              |
| ----------------- | --------------------- | --------------------------------------------- |
| Exposed channels  | 8 (channels 0–7)      | **6** (channels 0–5 routed to connectors J1–J6) |
| Channels 6 & 7    | Usable (SC6/7, SD6/7) | **Not routed**; do not expose to callers      |
| Default address   | Strap-dependent       | **0x70** (A2=A1=A0=0 via 10 kΩ pull-downs)    |
| RESET pin         | Host-controllable     | Pulled up on-board, **not** MCU-controllable  |
| Address change    | A0–A2 pins            | Only by reworking 0 Ω straps to VCC           |

This project configures `CONFIG_PAHUB_ADDRESS=0x72` in `sdkconfig.defaults`; the hardware straps must match.

## 30.2 Channel → Connector Map

| External Port | Connector | Channel | Control Byte   |
| ------------- | --------- | ------- | -------------- |
| Port 0        | J1        | 0       | 0x01           |
| Port 1        | J2        | 1       | 0x02           |
| Port 2        | J3        | 2       | 0x04           |
| Port 3        | J4        | 3       | 0x08           |
| Port 4        | J5        | 4       | 0x10           |
| Port 5        | J6        | 5       | 0x20           |
| (none)        | —         | —       | 0x00 (all off) |

## 30.3 Board-Level API Rules

* `unit_pahub_channel_set()` must reject channel indices `> 5` and `unit_pahub_mask_set()` must reject masks `> 0x3F` (board-invalid channels 6 and 7).
* Default to **all channels off (0x00)** after init.
* The board is intended for **same-address device coexistence**: enable **exactly one channel at a time** before each downstream transaction sequence.
* `unit_pahub_mask_set( 0x00 )` disables every port.
* Keep bus speed ≤ 400 kHz and total bus capacitance ≤ 400 pF (longer Grove cables add capacitance).

## 30.4 Recovery (no host RESET line)

Because the RESET pin is not host-controllable on this board, recover from faults by:

1. Writing `0x00` to deselect all channels.
2. Retrying a single-channel selection.
3. Power-cycling the module supply if a downstream device is holding SDA low, but only if that supply can be switched without resetting the MCU or other peripherals (see `pahub.md`).
4. Re-probing addresses `0x70`–`0x77` if the address straps were reworked.

## 30.5 Recommended Driver State

```c
struct pahub_state {
    uint8_t i2c_addr;       /* 0x70..0x77, default 0x70 */
    uint8_t selected_mask;  /* last written control byte; may desync after power cycle */
};
```

Treat the cached `selected_mask` as advisory; always tolerate desynchronization after a module power cycle by re-writing the desired channel.
